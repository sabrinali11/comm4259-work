⏺ Here's how tab 5 ("What does each model cost?") computes expected cost, in
  assignment_04/dashboard/app.py:

  1. It starts from confusion matrix counts. For every model run you trained on
  tab 4, and for two baselines ("predict positive for everyone" / "predict
  negative for everyone"), it has four counts on the testing data:
  - TP = predicted positive, actually positive
  - FN = predicted negative, actually positive
  - FP = predicted positive, actually negative
  - TN = predicted negative, actually negative

  This is built at lines 743–748, where the baselines' counts are derived
  directly from how many actual positives/negatives are in y_test, and each
  run's counts come from what you stored when you trained it.

  2. You enter a cost matrix (Step 2, around line 703–714): a dollar amount for
  each of those four outcomes (TP, FN, FP, TN). Benefits (TP, TN) should be 0 or
  negative; costs (FP, FN) should be 0 or positive. This is the "price tag" for
  each type of outcome — e.g., "a false negative costs us $X because we missed
  something we should have caught."

  3. The actual calculation (lines 750–751):
  table["expected cost ($)"] = (table.TP * cm["TP"] + table.FP * cm["FP"]
                                + table.FN * cm["FN"] + table.TN * cm["TN"])
  In plain language: for each option (baseline or run), multiply the number of
  cases in each outcome category by the dollar amount assigned to that category,
  then add the four products together. So if a run had 50 TPs and you said each
  TP is worth -$2 (a $2 benefit), that contributes -$100 to the total. Do that
  for all four categories and sum them — that sum is the "expected cost" for
  that option, totaled over the whole testing set.

  4. Cost per case (line 752) just divides that total by the number of testing
  rows, so you can compare options on a per-case basis regardless of how many
  rows exist.

  5. Ranking (line 753): the table is sorted ascending by expected cost, so the
  option with the lowest (most negative, if it's a net benefit) number appears
  first — that's the one declared "lowest expected cost" and highlighted in the
  chart (line 790 best = table.iloc[0]).

  One thing to flag per the "my own rules" section: this computation only runs
  after you click Calculate expected cost, and only once all four cost cells
  have valid entries (line 723, disabled=bool(problems)). If you change any
  dollar amount afterward, st.session_state.cost_matrix is cleared (line 736)
  and you have to click the button again — that's intentional, not a bug, so the
  displayed numbers always match the amounts currently in the boxes.
